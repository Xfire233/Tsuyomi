# Wenku8 vertical-slice acceptance matrix

All automated rows use sanitized recorded fixtures and a mocked host transport; no CI job solves or depends on live Cloudflare. Android host rows run in the currently active Standard profile; E-ink remains deferred until its explicit restoration pass. WebView/storage rows require an AVD or device, while live Wenku8 verification is a separate foreground, best-effort physical-device acceptance input.

The active first production milestone is a basic usable Standard Wenku8 reader: signed acceptance-source install, explicit controlled login, real root-neutral search, canonical Detail with integrated directory, exact chapter Reader, immediate adjacent-chapter navigation, unconditional local-only library pin, process recreation and semantic resume. It additionally includes host-validated real covers and a separately initiated read-only website-favourites list/copy-to-local flow. This is an intermediate Phase 4A milestone, not Phase 4A completion. Website ADD, remove, move, mirror calibration, background pulls and E-ink readiness are not part of this milestone.

Raw live HTML is never a durable content artifact. A live pass uses one predeclared public query/book, concurrency one and a bounded foreground request budget; it stops on repeated login, challenge, 403 or 429 outcomes. Only strictly validated normalized metadata, directory and opened `ReaderDocument` projections may enter offline storage. Fixture authoring replaces all live text, identities, URLs, account data and variable attributes before any file is written; exact live lengths/digests and authenticated account-library contents are forbidden evidence.

Temporary unattended-live authorization, granted 2026-08-30: until the real Wenku8 Search → Detail → Directory → Chapter → Reader chain passes, the debug validation host may preserve and reuse the current same-app controlled-WebView session in the normal encrypted Wenku8 origin partition without asking the user to log in again. If test cleanup removed that encrypted row while the process-global jar still contains the same controlled-session cookie, a debug-only one-time recovery may re-encrypt that cookie with the controlled WebView default/current user agent. No plaintext log/file, external-browser import, cross-source reuse, production fallback, hidden challenge automation, or extension access is authorized.


| Flow | Acceptance evidence |
|---|---|
| Install | Valid signed `org.tsuyomi.wenku8` `.hxp` installs; unsigned, altered, revoked, incompatible-host, path-traversal, and hash-mismatched packages are rejected before module evaluation. |
| Permission grant | The extension can request only declared HTTPS origins, optional read-only source Home, and remote-library operations. A package update adding an origin, cookie scope, WebView login, source Home, remote `add`/`remove`/`move`, or storage quota pauses for explicit approval. |
| Search | Fixture query returns normalized stable remote ID, title, author, cover, and canonical URL; malformed cards are skipped with structured diagnostics. Wenku8 search terms are serialized by the host as a GB18030 `application/x-www-form-urlencoded` query because the live legacy form interprets UTF-8 percent bytes as mojibake. The exact host-built GET remains the paused-request identity used by the explicit verified-page fallback. |
| Source Home | Route entry, restoration and login return perform zero requests. An explicit load requests a signed Wenku8 ranking page, admits only a concrete catalog list, and returns `SourceHomePage` schema v1 with bounded host-rendered filters, sections, paging cursor and normalized summaries. The extension cannot inject layout, arbitrary URLs, raw HTML, background refresh or website mutation. |
| Detail | Fixture detail maps metadata, tags, status, and cover without retaining source HTML as durable app state. |
| Directory | Fixture table of contents emits stable chapter IDs, ordered display labels, and URLs. Duplicate/changed display text does not alter the chapter identity. |
| Chapter | Fixture chapter is normalized into ordered paragraphs; empty or malformed content returns a typed source error rather than a crash. |
| Reader + progress | Open chapter, persist chapter ID plus text anchor/offset, recreate reader state, and restore the same locator. If the anchor is absent, use bounded fallback progress and report degraded precision. |
| Library | Add, rate, tag, shelf, and remove the book using `(sourceId, remoteBookId)`; uninstalling the extension makes the record dormant without deletion. |
| Read-only website favourites | Entry, refresh and copy selected/all are explicit foreground actions. Route entry, login return, restoration and generic refresh perform zero favourites requests. Copy writes only local library state, never website state. Live evidence uses no private account-library titles, IDs, counts or screenshots; deterministic signed fixtures own repeatable pagination/selection/error proof. |
| Remote library writes | Writeback is disabled by default. After the user grants declared `add`, `remove`, or `move` operations and enables writeback for Wenku8, a direct user action performs only the selected operation. Import, login checks, WebView closure, and refresh never write remotely. |
| Transfer | Export contains book identity, metadata, shelf membership, rating/tags, and progress, but contains no cookies, credentials, HTML cache, or source-local hidden IDs. |
| Rate/cache | Transport respects host concurrency/timeout/response limits. Repeated fixture reads demonstrate cache hit and invalidation behavior without contacting the live site. |
| Login boundary | Extension may request controlled WebView login only when the declared capability is granted; no code automates CAPTCHA, Cloudflare, or similar verification. |
| Android WebView | User completes manually driven login/verification in a controlled WebView. The encrypted source/origin partition retains declared-origin request cookies plus the exact user agent captured from that session; the host, not extension code, injects both. Re-entering verification for Wenku8 clears the global WebView jar, restores only Wenku8's encrypted declared-origin cookies with that exact user agent before the first load, and clears the global jar again on completion/cancel without deleting the verified encrypted session. Deterministic replay proves re-entry continuity and cross-source isolation. On 2026-08-30 the user confirmed that the real website remained logged in across re-entry, but a separately authorized second `SourceGatewayFactory → HostNetworkGateway → UrlConnectionHostHttpTransport` request still returned `SESSION_REQUIRED` with an encrypted session present. Direct cookie-plus-exact-UA transport is therefore best-effort. The active acceptance path is the explicit foreground fallback: `打开对应页面` visibly loads the exact paused GET; only allowed-origin HTTPS top-frame redirects preserve that request binding, and later non-redirect navigation invalidates it. `使用当前页面` then captures bounded memory-only HTML, matches the originating GET once, exposes the admitted final page URL to the signed parser, and persists only validated normalized output. |
| Android export | User exports a transfer JSON, selects it through the system file picker, and reimports it into a clean local profile with the same locator. |
| Android E-ink profile | **Deferred until the explicit E-ink restoration pass.** Retain the contract that forced `eInk` completes install, search, detail, directory, chapter, reader restore, library action and transfer import/export with explicit pagination, fixed chrome and immediate state replacement. |
| E-ink display evidence | **Deferred until restoration.** Physical E-ink evidence must still record model, Android version, effective profile, logical refresh policy, ghosting/refresh limitations, tap/volume-key behavior, image loading, dialog feedback and WebView return before any E-ink readiness claim. |
