Pinned production MOBI parser — third-party notices
===================================================

The production bundle is built from @lingo-reader/mobi-parser 0.4.6 at commit bc912542d9c09f144257205943c6bd3e421d8743. This directory vendors the exact upstream source files and a scoped local derivative; it does not modify or replace the pinned source. The guarded build adapter supplies descriptor-only resources, bounded expansion, exact MOBI byte-position anchors (including authored NCX offsets), MOBI7 NCX hierarchy preservation, and base32/cycle-safe KF8 resource resolution. The host adapter canonicalizes the image/jpg JPEG MIME alias, consumes the upstream author field, retains authored TOC/heading labels when projecting reading sections, and explicitly distinguishes untitled sections for localized numbered fallback labels. It also includes the exact shared XML parser source and pinned runtime dependency closure described below. Keep these notices with the bundle.

Only nonblank source navigation labels participate in authored section-title precedence. The private catalog preserves that provenance separately from localized display captions, retaining unlabeled navigation rows and targets without overriding real section headings.

Shared KF8 stylesheet references retain stable opaque resource identities. Native admission charges each immutable stylesheet source once against its distinct-source budget while preserving every cascade occurrence and the separate per-section application/work limits; source identities cannot be reused for changed CSS.

Pinned runtime dependencies live under vendor/dependencies/<package>@<version>/<package>, outside generated node_modules trees. source-pins.json retains upstream package-manager paths as provenance; the build maps those paths to the vendored layout and verifies the unchanged source hashes.

KF8 aid targets coexist with pre-existing authored HTML IDs through escaped, zero-text inline aliases at the same element start. Existing authored IDs and heading block identities are retained, and native anchor existence/uniqueness validation remains authoritative.
