# Documentation responsibility registry

This registry defines why each first-party document exists, when to read or update it, how far its authority extends, and when the document task is complete. It is navigation metadata, not a second copy of the documents' rules.

## Record contract

| Field | Meaning |
|---|---|
| Role / purpose | The question this document alone is intended to answer. |
| Trigger | Observable condition requiring the document to be read or updated. |
| Method | How to use it without reading unrelated material. |
| Scope / exclusions | Decisions it owns and nearby decisions it must not own. |
| Completion / stop | Evidence that the required reading or update is sufficient; linked documents are not read automatically after this point. |
| Lifecycle | Active authority/procedure/reference, accepted ADR, release record, or history. |

An environment-provided `AGENTS.md` may impose higher-priority agent instructions without being a versioned first-party document. A registered document is not mandatory merely because another document links to it; follow a link only when its Trigger matches the current task. Current user direction and the active agent authority order still override lower-authority records.

## Dispatch procedure

1. Bootstrap non-trivial work with the environment-provided agent instructions, `WORKSPACE.md`, the affected component `CONTRIBUTING.md`, current handoff when present, and required memory recall.
2. Classify the needed decision as Contract, Phase, Gate, Procedure, Policy, Evidence, State, or History using `WORKSPACE.md`.
3. Select the single owning row below. Read only its affected sections and any prerequisite explicitly named by the row.
4. Stop when the row's Completion condition is satisfied. Do not recursively read every referenced document.
5. If two active documents claim the same decision, use the authority order, reconcile one owner, remove the duplicate current rule, and extend the governance checks when the conflict is mechanically detectable.

## Lifecycle changes

- New first-party Markdown: add its row in this registry in the same change.
- Rename/move: use symbol/path-aware tooling where available, update every link, then replace the registry path; no alias document remains.
- Supersession: update the owning active document, mark the old document historical or remove it, and state the new owner. Two active interpretations are forbidden.
- Deletion: remove only after every inbound reference and retained authority has migrated; remove the registry row in the same change.
- README/changelog/retrospective text never becomes active product authorization merely because it is newer.
